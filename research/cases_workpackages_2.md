# 第二批补缺工作包：剩下的 85 种情况，分 7 包并行

来源：[`cases.json`](cases.json) 里 `now` 为 partial / missing 的条目。第一批已完成的见 `now: done06`。

## 通用验收标准

1. 一个效果一个文件：`scripts/h9/fx/<名字>.py`，导出 `FX`；W1–W6 不改共享文件（需要的话写进交接文档，由 W7 或主会话合并）。
2. 横屏 16:9、竖屏 9:16 各自排版；颜色走主题变量；文字、条数、图片张数用 `scripts/h9/fit.py` 自适应；竖屏遵守安全区（顶 200px、底 400px、下半屏右侧 120px）。
3. 每个效果至少一个真实口播演示 beat（数据核实并印出来源，示意内容标「示意」），放进本包演示片 `examples/<目录>/video.json`，横竖屏都渲染到 `renders/reel_<16x9|9x16>.mp4`。
4. 每个效果至少 3 种刻意不同的输入，写进 `examples/<目录>/variants.json` 和 `examples/stress/targets/<目录>.json`（格式同 data.json：`{base, beats:[{fx,...}]}`）。
5. `npx --yes hyperframes@0.8.191 check` 0 个 error；每页横竖屏截图自查；按 2 帧/秒抽查无死秒。
6. 确定性渲染；不调用付费接口；不下载新素材（网页查证可以）；本机不跑 TTS / 语音识别。
7. 交接文档写清：效果、参数、输入范围（references/inputs.md 的新行）、catalog.py 的 CAT / SUIT / DUR / PIT、已知问题。
