# 导演手册：从需求到交付，怎么把片子做得厉害

`craft.md` 管「别像 AI 默认款」，这一篇管「整条片子怎么立起来」：先想清楚、按关卡做、交付前自己当观众挑刺。方法来自两类公开分享：一是「拿一批参考视频教 AI 学一种剪辑风格」（逐字稿 + 抽帧 → 总结原则 → 按原则排参考板 → 再出片），二是「用大模型写代码做动画」的工作室规则（需求模板、关卡流程、打分自检循环）。

## 一、先写需求单，再动手

| 项 | 写什么 | 例子 |
|---|---|---|
| 一句话片子 | 这条片子要观众记住的一件事；后面每个决定都拿它来对 | 「同一条文案，17 种完全不同的成片」 |
| 参考 | 2–5 条你想接近的成片（链接 + 想学它哪一点） | 「学它的快切卡点」「学它的字体搭配」 |
| 节拍表 | 按秒排：**前 2 秒必须有钩子画面**，之后**每 3–5 秒一个视觉爆点**，每段写清「观众看见什么」 | `0–2s 成片最炸的一段` `2–6s …` |
| 屏幕文字 | 哪几句上大字、哪几句只留字幕（见第三节） | 全片大字 ≤ 3 句 |
| 素材 | 真实截图 / 录屏 / 数据和出处；**不编界面、不编数字** | 产品片只用真实界面 |
| 交付 | 画幅、时长、封面、文案、配乐署名 | 9:16 · 60–80 秒 |

## 二、按关卡做，不许跳关

每一关都有命令；不过关就回到出问题的那一关，不在成片上修修补补。

| 关 | 做什么 | 命令 | 过关标准 |
|---|---|---|---|
| 1 规划 | 需求单 + 节拍表 | `hat9.py brief new work/` | 一句话片子写得出来；节拍表每 3–5 秒有爆点 |
| 1′ 分镜检查 | 按节拍表写 video.json | `hat9.py brief check work/video.json --aspect 9:16` | 没有 P0：纯文字画面 ≤ 30%、没有撑 8 秒以上的画面、大字不重复字幕 |
| 2 静帧 | 每个 beat 一帧排成板 | `hat9.py stills work/video.json --aspect 9:16` | 板上每格（约手机大小）读得清、和邻格不同、和那句话有关 |
| 3 小样 | 只做最难的几秒（开场、快切） | `hat9.py sample work/video.json --range 0,4` | 带声音看，节奏和冲击对了 |
| 4 整片 | 全部 beat 接起来 | `hat9.py render work/video.json --aspect 9:16` | `check` 无 error |
| 5 打磨 | 节奏、转场、字号、颜色；快切段 | `hat9.py montage montage.json --into 成片.mp4` | 每刀卡拍、每刀写明对应哪句话 |
| 6 声音 | 人声干净、配乐卡拍、说话时压低、无人声段推上来 | 配乐旁有 `*.beats.json` 时自动卡拍；`"duck": true`；无人声段 beat 写 `"music": "up"` 或用 `montage` 快切 | `review` 的卡拍（无人声段 ≥ 70% 的刀在拍上 ±2 帧）、音画、配乐比人声低 ≥ 10 dB；约 -14 LUFS，峰值 < -1 dBTP，无 1.2 秒以上的空白 |
| 7 自检 | 静帧板 + 自动检查 + 打分 | `hat9.py review 成片.mp4 --video work/video.json`，`hat9.py review --gate review.md` | 无 P0；六项都 ≥ 8 |

## 三、画面硬规矩

- **大字不能只重复字幕**。屏幕上的大字要么是字幕里没有的信息（数字、对比、结论），要么干脆不要；口播段默认只留一层字幕。
- **不做 PPT 大字报**：纯色底 + 一行大字，全片最多 2–3 屏，留给最关键的话。
- **不许静止超过 2.5 秒**；每 2–4 秒画面上要有新东西（新元素、镜头运动、切换）。
- **手机上读得清**：要观众读的字，竖屏 1080 宽下不小于 36px；空心描边字只在高对比底上用；小窗口（终端、截图）要推近到占画面一半以上。
- **快切（无人声段）**：每一刀卡在节拍上（一拍或半拍）；只用一眼能看懂主体的画面，放它最好看的 0.5–1 秒动作，不截静止的中间帧；画面内容要和前后那句话相关。

## 三″、多样：同一个事实，换不同的载体

参考片（每秒 2 帧看完的抖音爆款）厉害的不是字怎么出现，而是**信息的形状一直在换**：同一个「数字」，它用了贴人边的大数、仪表、钟、马赛克、列表角标、截图圈注九种载体。我们的片子输在一句话居中全屏、再一句话居中全屏。

- **同一个事实，换不同的载体**。说「5%」可以是环形图、100 个小人亮 5 个、收据上的一行、截图里圈出来的数——先想「这个数长什么样」，再选效果。每个效果属于一个版式家族（`scripts/h9/form_families.json`：全屏大字 / 贴人 / 数据图 / 比喻 / 对比 / 界面 / 文档 / 实拍 / 快切……）。
- **全屏大字不能连着两个**。两个相邻 beat 不许同一家族；全屏大字最多占 25% 的 beat；60 秒以上的片子至少 5 个家族。`review.py --video video.json`（不用渲染）和 `brief.py check` 会查：`form-repeat`、`slogan-share`、`form-variety`。
- **主体留在画面里，只是换位置**。有真人、录屏或柴犬时，用 `meta.presenter` 让它整片都在：全屏 → 图表下的小卡 → 侧边 → 角落 → 回全屏，图表从它让出来的地方长出来。信息每 1–2 秒变一次，不需要硬切（见 `references/presenter.md`）。
- **一个贯穿的装置做章节**：`meta.device`（相机 / 浏览器 / 手机）+ 每章 `chapter: {label, bg}`，模式名和内容对上、每章一个底色世界（见 `references/device.md`）。

## 三′、声音硬规矩

- **卡在量出来的拍上**：配乐用素材库里带 `.beats.json` 的曲子，构建时换画面、转场、音效和画面冲击自动吸到拍上；对口播的 `"@词"` 不会被挪到词前面。
- **说话时压低，没人说话时推上来**：`"duck": true`（默认压 10 dB）；`gaps` 空出来的停顿里放 `montage` 快切，配乐自动推高 8 dB。
- **快切放进片子里做**：用 `"fx": "montage"` beat（自动卡拍、自动挑段、自动推配乐），不要先渲染再叠。
- **音效和画面同一帧**：音效写在 beat 的 `sfx` 里并带 `hit`（flash / dark / shake / punch），`review` 会逐帧核对。
- **演示要真**：讲工具就给真实操作（录屏、真实命令、真实输出），讲风格就让同一内容在不同风格里并排出现。
- **前后对比**用同一帧左右分屏或划屏，不要前后各闪一下。
- **吹什么就做到什么**：片子说「不重复」，自己就不能一种版式用到底；同一个效果全片不超过 3 次。

## 四、交付前自检（打分循环）

```bash
python3 scripts/hat9.py review work/renders/press_9x16.mp4 --video work/video.json [--ref 参考.mp4]
```

它会出每秒 2 帧的静帧板，并自动查：静止过久、前 2 秒有没有变化、切换间隔、纯色大字报的占比、大字是否只是重复字幕、同一效果用了几次、响度和峰值、空白、（给了参考片时）切得比参考慢多少；有配乐节拍时还查无人声段的刀是否卡拍、音效是否和画面冲击同帧、说话时配乐是否压得够低。然后**自己当观众把静帧板从头看到尾**，按下表给每项 1–10 分：

| 项 | 问自己 |
|---|---|
| 钩子 | 只看前 2 秒，会不会继续看？ |
| 手机可读 | 缩到手机大小，每屏要读的字读得清吗？ |
| 节奏 | 有没有超过 2.5 秒什么都不变的地方？ |
| 信息 | 画面有没有给出字幕之外的东西？ |
| 多样 | 版式、颜色、效果有没有一种用到底？ |
| 相关 | 每个画面（尤其快切）和那句话有关吗？ |

写下**最差的 3 个问题**，改掉，重新渲染、重新打分；**每项都 ≥ 8 才交付**：`hat9.py review --gate review.md` 会拒绝没打分、低于 8 分、还有 P0 或没写最差 3 处的表。交付时告诉用户实际检查了什么。

## 五、从参考视频学一种风格

想要某种「感觉」又说不清时：

1. 找 10–20 条同一风格的参考成片。
2. `hat9.py refs 参考*.mp4 --out work/refs [--transcribe]`：每条量节奏、每个镜头抽一帧排成带编号的参考板（R2-07 = 第 2 条第 7 帧），可选逐字稿，并生成 `principles.md`。
3. 在 `principles.md` 里总结 5–10 条**可执行的原则**，每条配 2–3 个帧编号（例如「两种字体：无衬线正文 + 斜体衬线强调词」「一条线贯穿全片串起元素」「插图在侧，文字在另一侧」）。
4. 按原则排一张参考板，确认原则覆盖了大部分镜头。
5. 用 `hat9.py style new <id> --from <最接近的风格>` 派生，把原则落到颜色、字体、版式和 CSS；先做一个场景对着参考板比，过关再铺开。
